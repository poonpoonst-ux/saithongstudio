# SAITHONG STUDIO

เว็บไซต์สตูดิโอสร้างสรรค์สองภาษา ใช้ HTML5, CSS และ Vanilla JavaScript หน้าอังกฤษอยู่ที่ `/` และหน้าไทยอยู่ที่ `/th/` ทั้งสองภาษามี URL ของตัวเอง เปิดลิงก์ไปยังหน้าบริการหรือผลงานชิ้นใดชิ้นหนึ่งได้โดยตรง

โฟลเดอร์ **`public/` คือเว็บไซต์สำหรับเผยแพร่** ส่วนไฟล์ด้านนอกใช้แก้ไขเนื้อหา สร้างหน้าเว็บ และเชื่อม GitHub กับ Netlify การสร้างเว็บใช้ Node.js และไลบรารีมาตรฐาน ระบบนี้ใช้ได้โดยไม่ต้องติดตั้งแพ็กเกจ npm เพิ่ม

## 1. เปิดเว็บไซต์ในเครื่อง

**เปิดดูทันทีบน Windows** คลิกขวาที่ ZIP เลือก **Extract All / แยกทั้งหมด** แล้วดับเบิลคลิก **เปิดเว็บไซต์.html** ในโฟลเดอร์ `saithong-studio` หน้าแรกภาษาไทยจะเปิดในเบราว์เซอร์ หากต้องการเริ่มเป็นภาษาอังกฤษ ให้เปิด `public/index.html` ควรเก็บโครงสร้างโฟลเดอร์ที่แตกไฟล์ไว้ด้วยกัน เพื่อให้หน้าเว็บหารูป วิดีโอ และไฟล์อื่นได้

### สำหรับผู้ที่ต้องการแก้ซอร์สหรือทดสอบผ่านเซิร์ฟเวอร์

1. แตกไฟล์ ZIP แล้วเปิดโฟลเดอร์ `saithong-studio` ที่มี `netlify.toml` หากได้รับโฟลเดอร์ซอร์สโดยตรง ให้เปิดโฟลเดอร์นั้น
2. ใช้ Node.js 22 ขึ้นไป เปิด Terminal หรือ PowerShell ในโฟลเดอร์นี้ แล้วตรวจด้วย `node --version`
3. เริ่มเซิร์ฟเวอร์ด้วยคำสั่งด้านล่าง

```sh
node scripts/serve.mjs
```

4. เปิด [หน้าแรกภาษาอังกฤษ](http://localhost:4173/) หรือ [หน้าแรกภาษาไทย](http://localhost:4173/th/) เมื่อแก้ไขข้อมูลหรือเทมเพลต ให้เปิด Terminal อีกหน้าต่าง รันคำสั่งสร้างเว็บ แล้วรีเฟรชเบราว์เซอร์

```sh
node scripts/build.mjs
```

5. หยุดเซิร์ฟเวอร์ด้วย `Ctrl+C` หากพอร์ตถูกใช้อยู่ ให้ตั้ง `$env:PORT='4175'` ใน PowerShell ก่อนรันเซิร์ฟเวอร์ แล้วเปิด `http://localhost:4175/`

ทั้งการเปิดไฟล์โดยตรงและการเปิดผ่านเซิร์ฟเวอร์ตัวอย่างใช้ตรวจแบบฟอร์มได้ เมื่อกรอกถูกต้องจะมีข้อความแจ้งว่าเป็นการแสดงตัวอย่าง การส่งคำสอบถามจริงใช้เว็บไซต์ที่เผยแพร่บน Netlify และเปิดใช้งาน Forms แล้ว

## 2. ไฟล์ที่ใช้แก้ไข

| ตำแหน่ง | ใช้ทำอะไร |
| --- | --- |
| `studio.config.json` | ข้อมูลติดต่อที่ยืนยันแล้ว โดเมน หมวดผลงาน รายละเอียดโปรเจกต์ และไฟล์โชว์รีล |
| `src/pages.mjs` | เนื้อหาหน้าแรก สตูดิโอ บริการ พอร์ตโฟลิโอ โชว์รีล และขั้นตอนการทำงาน |
| `src/services.mjs` | ชื่อ คำอธิบาย และหมวดของบริการทั้ง 19 รายการ รวมถึงขั้นตอนการผลิต |
| `src/contact.mjs` | ฟอร์มติดต่อ คำถามที่พบบ่อย นโยบายความเป็นส่วนตัว หน้าขอบคุณ และหน้า 404 |
| `src/layout.mjs` | เมนู ส่วนท้าย ปุ่ม และโครง HTML ที่ใช้ร่วมกัน |
| `scripts/build.mjs` | สร้าง HTML ทั้งสองภาษา ตลอดจน metadata, sitemap และ robots |
| `public/assets/styles/site.css` | สี ฟอนต์ ระยะห่าง และเลย์เอาต์แต่ละขนาดจอ |
| `public/assets/scripts/site.js` | เมนูมือถือ การจำภาษา ตัวกรอง แกลเลอรี และการตรวจฟอร์ม |
| `public/assets/images/` | โลโก้ favicon ภาพเปิดหน้าเว็บ ภาพแชร์ และโปสเตอร์วิดีโอ |
| `public/assets/projects/<slug>/` | ไฟล์ WebP ของผลงานแต่ละรายการ |
| `public/assets/videos/` | วิดีโอที่เล่นด้วยเครื่องเล่นมาตรฐานของเบราว์เซอร์ |
| `public/_headers`, `public/_redirects` | ส่วนหัว HTTP และหน้า 404 สำหรับ Netlify |
| `netlify.toml` | คำสั่ง build และโฟลเดอร์ที่เผยแพร่ |

เนื้อหาใน `src/` และ `studio.config.json` เป็นแหล่งแก้ไขหลัก เมื่อ build โปรแกรมจะสร้างไฟล์ HTML ใน `public/` ใหม่ ส่วน CSS, JavaScript, รูปภาพ และวิดีโอใน `public/assets/` แก้ไขได้โดยตรง

## 3. ที่มาของภาพและข้อมูลที่รอเจ้าของสตูดิโอ

- ชุดอ้างอิงที่ได้รับประกอบด้วยภาพ UI 6 ภาพและแบนเนอร์ 2 ภาพ โฟลเดอร์ Logo, Portfolio, Videos และ Documents ว่างในวันที่จัดทำ
- โลโก้บนเว็บไซต์ตัดจากส่วนหัวของภาพ UI หน้าแรก เก็บรูปทรง ตัวอักษร และคำว่า BY ตามภาพต้นฉบับ ภาพหลักใช้ส่วนคอลลาจที่ปรากฏในภาพอ้างอิง
- ภาพในแกลเลอรีทั้ง 5 ชุดเป็นรายละเอียดจากแบนเนอร์ “Saithong Creative Studio Showcase” และ “Saithong Studio Creative Portfolio Banner” ชื่อชุดบรรยายสิ่งที่ปรากฏในภาพ
- โชว์รีลความยาว 24 วินาทีเป็นการตัดต่อภาพนิ่งจากชุดงานที่ได้รับ ไม่มีเสียง หากมีวิดีโอผลงานฉบับจริง สามารถนำมาแทนได้ตามขั้นตอนด้านล่าง
- **รอข้อมูลจากสตูดิโอ** ได้แก่ โดเมนจริง อีเมลติดต่อ เบอร์โทร ลิงก์บัญชีสังคมออนไลน์ที่ยืนยันแล้ว และอีเมลสำหรับรับคำสอบถาม ข้อมูลเหล่านี้เว้นว่างไว้ ช่องทางที่ใช้ติดต่อในเว็บไซต์คือแบบฟอร์ม
- ก่อนเปิดใช้จริง เจ้าของควรตรวจว่านโยบายความเป็นส่วนตัวตรงกับวิธีจัดเก็บข้อมูลและการจัดการคำขอของสตูดิโอ หากมีข้อกำหนดระยะเวลาจัดเก็บหรือผู้รับผิดชอบเฉพาะ ให้เพิ่มที่ `src/contact.mjs` ทั้งสองภาษา

## 4. เปลี่ยนภาพและเพิ่มผลงาน

1. เปิด `studio.config.json` แล้วหารายการใน `projects` ใช้ `slug` เพื่อระบุโฟลเดอร์ของงาน เช่น `public/assets/projects/character-studies/`
2. ถ้าต้องการสลับเฉพาะภาพ ให้แทนที่ `cover.webp` และ `detail.webp` ด้วยไฟล์ WebP ที่มีเนื้อหาตรงกับคำบรรยาย แนะนำให้ครอปภาพปกโดยเผื่อขอบ เพราะการ์ดจะครอปภาพตามขนาดหน้าจอ แกลเลอรีและไลต์บ็อกซ์แสดงภาพเต็ม
3. ถ้าจะเพิ่มงาน ให้คัดลอกรายการเดิมใน `projects` ตั้ง `slug` ใหม่เป็นตัวพิมพ์เล็กภาษาอังกฤษ ตัวเลข และขีดกลาง สร้างโฟลเดอร์ชื่อตรงกัน ใส่ `category` เป็นคีย์ที่มีอยู่ใน `categories`
4. แก้ `title`, `subtitle`, `description` และ `credit` ให้ตรงกับงานจริง ทั้ง `en` และ `th` เพิ่มรูปในอาร์เรย์ `gallery` ได้ รูปแรกเป็นปกของการ์ด แต่ละรูปต้องมี `file` และคำอธิบาย `alt.en`, `alt.th`
5. รัน `node scripts/build.mjs` ตรวจหน้า Portfolio และหน้ารายละเอียดทั้งสองภาษา ดูเนื้อหาภาพเต็มและลองปุ่มก่อนหน้า/ถัดไป ใช้ปุ่ม Esc เพื่อปิด
6. เมื่อเอารายการออกจาก `projects` แล้ว build อีกครั้ง หน้ารายละเอียดเดิมที่ตัวสร้างเคยสร้างไว้จะถูกนำออกจากผลลัพธ์ รูปต้นฉบับยังอยู่ในโฟลเดอร์สื่อ

ถ้าจะเปลี่ยนโชว์รีล ให้วางวิดีโอ MP4 (H.264) หรือ WebM ใน `public/assets/videos/` แล้วแก้ `showreel.file` และ `showreel.poster` ให้เป็นพาธที่เริ่มด้วย `/assets/` แก้คำอธิบายสองภาษาใน `showreel.description` และคำบรรยายแต่ละช่วงเวลาใน `showreel.scenes` ให้ตรงกับลำดับภาพด้วย หากวิดีโอใหม่มีคำพูด ให้เพิ่มไฟล์คำบรรยายและแท็ก `track` ในเครื่องเล่นที่ `src/pages.mjs`

## 5. แก้ช่องทางติดต่อ

1. เปิด `verifiedContacts` ใน `studio.config.json` ใส่เฉพาะบัญชีที่เจ้าของสตูดิโอตรวจสอบแล้ว
2. ช่อง `email` ใส่เฉพาะที่อยู่อีเมล ช่อง `phone` ใช้หมายเลขติดต่อจริงพร้อมรหัสประเทศ สำหรับ `facebook`, `line`, `instagram`, `youtube`, `tiktok` ให้ใช้ URL แบบ HTTPS ที่เปิดไปยังบัญชีจริง
3. ค่าว่างจะซ่อนช่องทางนั้น หลัง build ลิงก์จะแสดงในส่วนท้ายของทุกหน้า ลองเปิดลิงก์จากมือถือและเดสก์ท็อป
4. อีเมลสาธารณะแก้ในไฟล์นี้ ส่วนอีเมลผู้รับแจ้งเตือนฟอร์มตั้งค่าใน Netlify ตามหัวข้อ 8 เจ้าของเลือกใช้คนละที่อยู่ได้

## 6. นำซอร์สขึ้น GitHub

1. เข้าสู่ระบบ GitHub และสร้าง repository ว่าง เช่น `saithong-studio` เลือกสิทธิ์เข้าถึงตามต้องการ เว้นการสร้าง README อัตโนมัติสำหรับการนำซอร์สชุดนี้ขึ้นครั้งแรก
2. เปิด Terminal ในโฟลเดอร์ที่มี `netlify.toml` สั่งการดังนี้

```sh
git init -b main
git add .
git commit -m "Add bilingual SAITHONG STUDIO website"
```

3. คัดลอก URL แบบ HTTPS ของ repository ของคุณ แล้วแทนที่ `YOUR_REPOSITORY_URL` ในคำสั่งต่อไปนี้

```sh
git remote add origin YOUR_REPOSITORY_URL
git push -u origin main
```

4. ตรวจว่า GitHub มี `src/`, `scripts/`, `public/`, `studio.config.json` และ `netlify.toml` อยู่ในระดับรากของ repository หากเปิดการยืนยันตัวตน ให้ทำตามขั้นตอนของ GitHub ผ่านเบราว์เซอร์ [คู่มือ GitHub](https://docs.github.com/en/migrations/importing-source-code/using-the-command-line-to-import-source-code/adding-locally-hosted-code-to-github)

## 7. เผยแพร่บน Netlify

### เชื่อม GitHub เพื่อ deploy อัตโนมัติ

1. ลงชื่อเข้าใช้ Netlify เลือกทีมและแผน Free ตามที่ต้องการ ใช้โดเมนย่อยที่ Netlify จัดให้ได้ ดูโควตาของบัญชีในแดชบอร์ด [ข้อมูลการใช้งาน Forms](https://docs.netlify.com/manage/forms/usage-and-billing/)
2. เลือก **Add new project → Import a Git repository → GitHub** ให้สิทธิ์เฉพาะ repository ที่ใช้ แล้วเลือก branch `main`
3. เว้น Base directory ว่างเมื่อไฟล์อยู่ที่รากของ repository ค่า **Build command** คือ `node scripts/build.mjs` และ **Publish directory** คือ `public` ทั้งสองค่ากำหนดไว้ใน `netlify.toml`
4. เลือก Publish หรือ Deploy ตามที่หน้าจอแสดง รอจนสถานะเป็น Published เปิด URL ของโปรเจกต์ในเบราว์เซอร์ ตรวจการตั้งค่าการเข้าถึงให้ตรงกับกลุ่มผู้ชมที่ต้องการ [คู่มือ deploy จาก repository](https://docs.netlify.com/start/quickstarts/deploy-from-repository/)
5. เปิด `/sitemap.xml`, `/robots.txt` และดู source ของหน้าแรก ค่า canonical, hreflang และ og:image ควรขึ้นต้นด้วยโดเมน HTTPS ของเว็บ ค่าที่ใช้เรียงลำดับจากตัวแปร `SITE_URL` → `siteUrl` ใน config → ตัวแปร `URL` ที่ Netlify ให้ขณะ build [ตัวแปร build ของ Netlify](https://docs.netlify.com/build/configure-builds/environment-variables/)
6. แก้ไขซอร์สแล้ว commit และ push ไปยัง `main` เมื่อเชื่อม Git แล้ว Netlify จะ build และ deploy เวอร์ชันใหม่

### อัปโหลด public ด้วยตนเอง

หากใช้การลากโฟลเดอร์แทนการเชื่อม Git ให้สร้างโปรเจกต์แบบ manual deploy หรือใช้โปรเจกต์ที่มีอยู่ เมื่อทราบ URL จริงแล้ว ใส่ origin ของเว็บ เช่น URL HTTPS ที่คัดลอกจาก Netlify ลงใน `siteUrl` โดยใช้เฉพาะโดเมน แล้วรัน `node scripts/build.mjs` ลาก **โฟลเดอร์ `public`** ที่สร้างเสร็จเข้าไปยังพื้นที่ manual deploy ของโปรเจกต์ หากใช้การอัปโหลดครั้งแรกเพื่อขอ URL ให้ build และอัปโหลดซ้ำหลังได้ URL

ไฟล์ชุดเริ่มต้นใช้ `http://localhost:4173` สำหรับ SEO ของพรีวิว การ build ด้วยโดเมนจริงจะอัปเดตลิงก์ SEO ทั้งไซต์ การอัปโหลดไฟล์แบบ manual ใช้ผลลัพธ์ที่ build ไว้บนเครื่อง [คู่มือ Netlify Drop](https://docs.netlify.com/site-deploys/create-deploys/#drag-and-drop)

## 8. เปิดรับคำสอบถามและตั้งอีเมลแจ้งเตือน

1. เข้าโปรเจกต์ใน Netlify เปิด **Forms → Enable form detection** หากเคยปิด ให้ไปที่ Forms → Form detection แล้วเปิดอีกครั้ง
2. **Deploy อีกครั้งหลังเปิด detection** ระบบจะสแกน HTML ใน `public/contact/index.html` และ `public/th/contact/index.html` ทั้งสองหน้าใช้ชื่อ `project-inquiry` และชื่อฟิลด์ชุดเดียวกัน
3. ตรวจใน Forms ว่าพบ **project-inquiry** ฟอร์มมี `method="POST"`, `data-netlify="true"`, hidden `form-name` และ honeypot `bot-field` Netlify ประมวลผลมาร์กอัปขณะ deploy จึงอาจเห็น HTML บนเว็บไซต์จริงต่างจากต้นฉบับ [คู่มือตั้งค่า Netlify Forms](https://docs.netlify.com/manage/forms/setup/)
4. เปิด **Forms → Submission notifications** เพิ่มการแจ้งเตือนแบบอีเมล เลือกฟอร์ม `project-inquiry` และกรอกอีเมลผู้รับที่สตูดิโอยืนยันแล้ว ถ้าระบบส่งอีเมลยืนยัน ให้ผู้รับกดยืนยันก่อนทดสอบ หากบัญชีกำหนดให้ใช้สมาชิกทีม ให้เลือกอีเมลสมาชิกที่ใช้งานได้ [คู่มือการแจ้งเตือน](https://docs.netlify.com/manage/forms/notifications/)
5. เปิดหน้า Contact บน **โดเมน Netlify ที่เผยแพร่แล้ว** ส่งคำสอบถามทดสอบด้วยอีเมลที่คุณตรวจรับได้ ทดสอบภาษาไทยและอังกฤษแยกกัน ตรวจว่าภาษาตรงกับหน้าขอบคุณ ตามลำดับ `/th/thank-you/` และ `/thank-you/`
6. เปิด Forms → project-inquiry ตรวจว่ามีรายการใหม่พร้อมรายละเอียดและค่า `language` จากนั้นตรวจกล่องจดหมายปลายทางและโฟลเดอร์สแปม การเข้าหน้าขอบคุณผ่าน URL โดยตรงใช้ตรวจรูปแบบหน้าได้ การยืนยันว่ารับข้อมูลแล้วให้ดูรายการ submission ใน Netlify
7. ถ้าไม่พบฟอร์ม ให้ตรวจ Publish directory, Form detection และ deploy ใหม่ ถ้ามีรายการใน Forms แล้วแต่อีเมลยังไม่ถึง ให้ตรวจผู้รับ การยืนยันอีเมล และตัวกรองจดหมาย หากรายการถูกจัดเป็นสแปม ให้ตรวจมุมมองสแปมใน Forms

การส่งข้อมูลใช้การ POST ของเบราว์เซอร์ หน้าเว็บรอผลตอบกลับจากโฮสต์ การพรีวิวในเครื่องใช้สำหรับตรวจเลย์เอาต์และข้อความแจ้งข้อผิดพลาดเท่านั้น ขั้นตอนตรวจรายการและอีเมลข้างต้นต้องทำบนบัญชี Netlify ที่จะใช้รับงานจริง

## 9. เชื่อมโดเมนของสตูดิโอ

1. ภายในโปรเจกต์ ไปที่ **Domain management → Production domains → Add a domain** แล้วเลือกเพิ่มโดเมนที่เป็นเจ้าของ
2. ทำตามขั้นตอนยืนยันโดเมน เลือกใช้ DNS ของผู้ให้บริการเดิมหรือ Netlify DNS กรณีใช้ DNS เดิม ให้คัดลอกชนิดระเบียน ชื่อ และค่าปลายทางจากคำแนะนำของโปรเจกต์โดยตรง เก็บระเบียนอีเมลที่ใช้งานอยู่ เช่น MX และ TXT [คู่มือโดเมน Netlify](https://docs.netlify.com/manage/domains/get-started-with-domains/)
3. รอ DNS กระจาย เลือกโดเมนหลัก และตรวจใบรับรองที่ Domain management → HTTPS เปิดทั้งหน้าแรกและหน้าติดต่อผ่าน HTTPS [คู่มือ HTTPS](https://docs.netlify.com/manage/domains/secure-domains-with-https/https-ssl/)
4. ตั้ง `siteUrl` หรือ `SITE_URL` เป็น origin ของโดเมนหลัก แล้ว deploy อีกครั้ง ตรวจ `sitemap.xml`, `robots.txt`, canonical และภาพแชร์บนโดเมนใหม่
5. ทดสอบฟอร์มบนโดเมนใหม่อีกครั้ง ตรวจสถานะ HTTP 404 ของ URL ที่ไม่มีอยู่ ทั้งเส้นทางภาษาอังกฤษและเส้นทางที่ขึ้นต้นด้วย `/th/`

## 10. ตรวจหลังแก้ไข

- เปิดหน้าแรก About, Services, Portfolio, Showreel, Process, Contact, Privacy, Thank You และ 404 ทั้งสองภาษา ลองเมนูมือถือและปุ่ม Tab ใต้เมนูหลัก
- สลับภาษาในหน้ารายละเอียดผลงานหรือในหน้าที่เปิดตัวกรองไว้ จากนั้นเปิดหน้าแรกอีกครั้ง เพื่อตรวจว่าจำภาษาที่เลือก
- เปิดการ์ดผลงาน ลองขยายภาพ ใช้ปุ่มซ้าย/ขวาและ Esc แล้วตรวจว่าโฟกัสกลับไปยังภาพเดิม
- เลือกขอใบเสนอราคาจากรายการบริการ ตรวจว่าฟอร์มเลือกบริการที่ตรงกัน ลองไม่กรอกช่องบังคับและใส่อีเมลไม่สมบูรณ์ ข้อความจะแสดงในภาษาของหน้า
- เปิดโชว์รีล กดเล่น หยุด และเลื่อนไปกลางคลิป ตรวจที่ขนาดมือถือ แท็บเล็ต และเดสก์ท็อป

ชุดส่งมอบมี 30 หน้า HTML รวมทั้งสองภาษาและหน้ารายละเอียดผลงาน 5 ชุด ทดสอบใน Chrome ที่ความกว้าง 320, 390, 768, 1024 และ 1440 พิกเซล ตรวจปลายทางลิงก์และแองเคอร์ ทดสอบสลับภาษา ตัวกรอง ปุ่มแกลเลอรี เมนูมือถือ การเลือกบริการล่วงหน้า และการแจ้งข้อผิดพลาดของฟอร์มในเครื่อง การยืนยันรายการจริงใน Netlify และอีเมลแจ้งเตือนเป็นขั้นตอนหลังเผยแพร่ในหัวข้อ 8
